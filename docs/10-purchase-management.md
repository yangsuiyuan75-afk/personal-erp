# 10. 采购管理

## 1. 页面

- 采购渠道；
- 供应商；
- 采购人员；
- 采购报价；
- 采购订单；
- 采购收货；
- 采购退货；
- 应付查看。

## 2. 采购报价

报价维度：

```text
SKU + Supplier + PurchaseChannel + Buyer + MinQuantity + EffectiveDate
```

报价仅用于推荐。采购订单确认时保存成交价快照。

## 3. 采购订单状态

- DRAFT
- CONFIRMED
- PARTIALLY_RECEIVED
- RECEIVED
- CANCELLED

支持分批收货。

## 4. 收货过账

确认收货后：

- 生成库存流水；
- 增加库存；
- 更新移动平均成本；
- 创建批次；
- 产生应付；
- 更新采购订单累计收货量。

## 5. 采购退货

采购退货减少库存并减少/冲销应付。

已付款情况下形成供应商退款应收或后续抵扣，不直接删除历史付款。

## 6. Phase 3 实现结果

- 有效采购报价按 SKU、供应商、采购渠道、采购员维度检查时间区间重叠；
- 采购订单创建时把输入成交单价保存到明细，后续报价变化不影响历史订单；
- 采购员必须已关联所选采购渠道，主数据停用后不能创建新业务；
- 订单确认后支持多张收货单，收货累计量不得超过订购量；
- 收货过账、库存余额、移动平均成本、采购批次、应付和订单状态在同一 Serializable 事务完成；
- 采购退货引用原收货明细，FIFO 分配被限制在指定原采购批次；
- 未付款部分通过 `PayableAdjustment` 冲减；已付款或超过未付余额的部分生成 `SupplierCredit`，不改写历史付款；
- 所有收货和退货过账均要求 `Idempotency-Key`，相同请求不会重复入账；
- 中文采购页面统一展示报价、订单、收货、退货、应付与供应商退款，并保持查询 URL 可恢复。
